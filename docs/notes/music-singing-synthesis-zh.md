# 歌声合成 (SVS)：技术研究笔记

截至 2025–2026 年歌声合成领域的技术现状。涵盖声学建模、歌声专用表示、可控歌声生成、歌声转换、数据集和评测。

---

## 1. 什么是 SVS

歌声合成（Singing Voice Synthesis）从符号输入（歌词 + 乐谱）或文本生成歌声音频。它位于 TTS、音乐生成和音频合成的交叉点。

**SVS 与 TTS 的区别**：

| 维度 | TTS | SVS |
|------|-----|-----|
| 音域 | 窄（说话音高） | 宽（音乐音高，2+ 八度） |
| 时长 | 韵律性、语言依赖 | 音乐性（音符时长，绑定乐谱） |
| 颤音 | 极少 | 核心艺术表现手段 |
| 发声 | 连续语音 | 持续音、花腔、一音多词 |
| F0 控制 | 粗糙 | 细粒度（半音 + 音分） |
| 风格 | 对话式 | 艺术性、流派依赖 |

**SVS 与音乐生成的区别**：音乐生成产出完整编曲。SVS 专注于*歌声*这一独特的音色和表现实体，以歌词为主要条件信号。

---

## 2. 管线架构

典型 SVS 系统：

```
输入：歌词 + 乐谱（音高、时长、音素）
    ↓
前端：文本/音素处理 + 乐谱解析
    ↓
声学模型：生成声学特征（mel 频谱图、F0、s/δ）
    ↓
声码器：将声学特征转为波形
    ↓
输出：歌声音频
```

### 2.1 前端

- **歌词转音素**：针对特定语言的音素转换（G2P）
- **乐谱解析**：从 MusicXML、MIDI 或自定义格式提取音符音高、时长、音素边界
- **韵律预测**：部分系统预测歌声特有韵律（乐句边界、呼吸标记）

### 2.2 声学模型

生成时间对齐的声学特征：

| 特征 | 描述 | 作用 |
|------|------|------|
| **Mel 频谱图** | 时频表示 | 主要输出，输入声码器 |
| **F0（基频）** | 时域基频轮廓 | 控制歌声音高 |
| **s/δ** | 有声/无声标志 + 时长偏差 | 气息感控制 |

### 2.3 声码器

| 声码器 | 类型 | 备注 |
|---------|------|------|
| **HiFi-GAN** | GAN-based | 标准基线，快速推理 |
| **DiffWave** | Diffusion-based | 高质量，较慢 |
| **Vocos** | Transformer-based | 近期，质量-速度平衡好 |
| **SoundStream / EnCodec** | 神经编解码器 | 端到端系统中使用 |

## 3. 关键模型演进

### 3.1 古典方法（2020 年前）

- **HMM-based SVS**（2000s–2010s）：基于隐马尔可夫模型，产出机械但可懂的歌声。表现力有限。
- **统计参数方法**：用 DNN 从音素/音符序列预测 mel 频谱图 + F0。自然度改善但仍呈"歌声化语音"质感。

### 3.2 神经声码器时代（2019–2022）

HiFi-GAN 等高质量神经声码器的引入使相同声学模型的输出质量显著提升。

### 3.3 扩散模型时代（2022–至今）

| 模型 | 描述 |
|-------|------|
| **DiffSinger (2021, 2022 更新)** | 基于扩散的 mel 频谱图生成。开创性开源 SVS 系统。支持多说话人、多语言。架构：U-Net 扩散，条件为音素 + 音高 + 时长。 |
| **SingSong (Google, 2023)** | 先分离歌声再重合成。扩散方法。 |
| **OpenDiffSinger** | DiffSinger 社区 fork，多说话人、多语言、快速推理扩展 |

### 3.4 端到端与大模型时代（2024–2026）

| 模型 | 描述 |
|-------|------|
| **ACE Singer (ACE Studio)** | 商业 SVS 系统，DAW 集成，多语言，多合成引擎 |
| **RDCM (2025)** | 循环扩散组合模型，长结构连贯歌声 |
| **音乐基础模型中的歌声** | ACE-Step、MusicGen 扩展等包含歌声生成能力 |

**对 AI 的意义**：SVS 正在与通用音频生成融合。MusicGen、AudioLDM 2 等能产出近似歌声但缺乏专用 SVS 的细粒度控制（音素级时序、精确音高）。前沿方向是在通用生成框架中的*可控*歌声。

## 4. 歌声专用表示

### 4.1 乐谱表示

| 格式 | 描述 | AI 相关性 |
|------|------|---------|
| **MusicXML** | 标准乐谱格式 | 音高 + 时长 + 歌词 + 力度 |
| **MIDI** | 音符事件 + 时序 | 音高和时序，但无歌词/音素 |
| **SVS 专用格式** | 自定义（如 DiffSinger 的 DS 格式） | 音素级对齐 + 音高 + 时长 |

### 4.2 音高表示

| 表示 | 描述 | 用途 |
|------|------|------|
| **MIDI 音符号** | 离散半音 | 粗糙条件 |
| **连续 F0** | Hz 基频 | 精细音高控制 |
| **音分 F0** | 半音 + 音分偏差 | 微分音表现力 |
| **音高轮廓** | 归一化音高轨迹 | 音高形状建模 |

**颤音建模**：颤音通常 5–7 Hz，深度 20–50 音分。大多数 SVS 系统隐式学习颤音（从数据中），而非显式建模。

## 5. 可控歌声生成

### 5.1 可控维度

| 维度 | 控制方法 | 备注 |
|------|---------|------|
| **音高** | F0 条件、音高校正 | 最基础控制 |
| **音色** | 说话人嵌入、参考音频 | 歌手身份 |
| **风格** | 流派/情绪标签、风格嵌入 | 流行 vs. 歌剧 vs. 民谣 |
| **表现力** | 颤音深度、气息感、动态 | 艺术控制 |
| **语言** | 音素集、G2P 模型 | 多语言支持 |
| **时长** | 音符时长、速度 | 速度控制 |
| **发声技巧** |  belts、假声、 vocal fry | 高级控制 |

### 5.2 方法对比

| 方法 | 原理 | 权衡 |
|------|------|------|
| **乐谱条件** | 音高 + 音素 + 时长作为输入 | 精确但需要准确乐谱 |
| **参考音频** | 编码参考歌手的音色+风格 | 自然音色但可控性差 |
| **文本 + 音高** | 文本歌词 + 音高轮廓 | 直观但粗糙 |
| **解耦表示** | 潜在空间中分离音高/音色/风格 | 最灵活，最难训练 |

## 6. 歌声转换

歌声转换（SVC）改变歌手身份同时保持音高和歌词：

| 方法 | 描述 | 局限 |
|------|------|------|
| **声学特征转换** | 用歌手专用模型转换 mel/F0 | 需要并行数据 |
| **扩散转换** | 以目标说话人为条件的扩散模型 | 质量好，需要说话人嵌入 |
| **内容-风格解耦** | 潜在空间中分离内容（音高/歌词）和风格（音色） | 最灵活，训练难 |
| **So-VITS-SVC** | 基于 VITS 的开源 SVC | 流行但质量因说话人而异 |

**核心挑战**：转换过程中保持音高准确和音素时序。许多 SVC 系统引入音高漂移或时序伪影。

## 7. 数据集

### 7.1 公开 SVS 数据集

| 数据集 | 语言 | 说话人数 | 内容 | 备注 |
|---------|------|----------|------|------|
| **Opencpop** | 中文 | 1 | ~100 首歌，流行 | 中文 SVS 研究常用 |
| **M4Singer** | 中文 | 8 | 92 首歌，流行/民谣 | 多说话人中文 |
| **NUS48E** | 英文 | 4 | 48 段歌曲 | 多风格 |
| **JSUT Song** | 日文 | 1 | 100 首歌 | 日文 SVS 基准 |
| **Kiritan** | 日文 | 5 | 163 首歌 | 多说话人日文 |

### 7.2 数据挑战

- **对齐**：歌声的音素-音频对齐比语音更难（持续音、颤音、花腔）。
- **多语言稀缺**：高质量歌声数据主要存在于中文、日文和英文。小语种严重不足。
- **版权**：从商业录音衍生的歌声数据集有许可限制。

## 8. 评测

### 8.1 客观指标

| 指标 | 描述 |
|------|------|
| **F0 RMSE** | 音高轮廓的均方根误差（音分） |
| **F0 correlation** | 预测与真实 F0 的 Pearson 相关系数 |
| **Mel L1/L2** | 频谱图重建质量 |
| **MCD** | Mel 倒谱失真 — 音色质量相似度 |
| **音素准确率** | 歌词可懂度 |
| **说话人相似度** | 说话人嵌入余弦相似度（音色） |

### 8.2 主观指标

| 指标 | 描述 |
|------|------|
| **MOS** | 整体质量评分 |
| **音高准确率** | 人工评分音高正确性 |
| **自然度** | 歌声听起来多自然 |
| **说话人相似度** | 与目标歌手多相似 |

### 8.3 评测挑战

- **没有标准基准**：不像 MIR 有 GTZAN/MAESTRO，SVS 没有通用接受的基准数据集和评测协议。
- **主观偏好主导**：客观指标（F0 RMSE、MCD）与人类对歌声质量的偏好相关性差。
- **缺失维度**：当前评测很少衡量音乐性、风格真实度或情感传达。

## 9. 开放问题

### 9.1 技术挑战

- **长结构连贯性**：在完整歌曲（3–5 分钟）上保持一致音色和音高准确。大多数系统在 10–30s 片段上评测。
- **表现力控制**：对颤音、气息感、动态和发声技巧的细粒度控制仍然有限。
- **Zero-shot 歌声**：在没有该声音训练数据的情况下生成歌声。
- **多轨歌声**：生成伴奏 + 歌声，正确处理混音。
- **实时 SVS**：低延迟歌声合成用于交互式应用（卡拉 OK、游戏）。

### 9.2 数据与文化挑战

- **小语种**：大多数 SVS 研究聚焦中文、日文和英文。
- **风格多样性**：歌剧、民谣、流行、说唱式演唱需要不同建模方法。
- **音素对齐**：歌声的音素-音频对齐因持续音和花腔而比语音难得多。

---

## 10. SVS 与 AI 音乐生态

| 相关领域 | 关联 |
|-----------|------|
| **TTS** | 共享管线。SVS 可受益于 TTS 在表现力上的进展 |
| **音乐生成** | SVS 是全曲生成的"人声层"（Suno, Udio） |
| **音源分离** | 歌声提取为 SVS 提供训练数据 |
| **音频编解码器** | EnCodec、DAC 等使 token 空间的端到端歌声生成成为可能 |
| **歌声转换** | SVC 为现有录音改变声音 — 与语音转换相关 |

**前沿**：SVS 和文本到音乐的边界正在模糊。MusicGen 能"唱歌"（某种程度上），专用 SVS 模型也在融入更多音乐上下文。未来可能涉及统一模型，能从专用表示生成*任何*音乐音频包括歌声。
