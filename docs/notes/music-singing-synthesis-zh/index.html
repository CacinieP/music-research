    歌声合成（SVS）：技术研究笔记¶

    内容核对日期：2026-09-19。涵盖乐谱条件歌声、声学模型、波形生成、可控性、歌声转换、数据集与评测。

    English version: music-singing-synthesis.md

    1. 任务定义¶

    在乐谱条件的歌声合成中，歌词和音符指定演唱内容。系统预测发音时序与富有表现力的声学特征，再生成歌声波形。文本到歌曲模型还可能创作旋律和伴奏；这种更广泛的任务不等于精确乐谱控制。

    方面 典型语音合成 乐谱条件歌声合成
    音高 语言语调和表达 音符目标与表现性偏移
    时序 语言韵律 音乐时序加音素级咬字
    持续声音 元音通常较短 长元音和音符过渡很重要
    装饰 随语言变化的音高运动 可包括颤音、滑音和一字多音
    控制 文本、声音、韵律 歌词、音符、时序、声音和表现力

    这些是倾向而非硬边界。歌唱不必跨越两个八度，也不必使用颤音。Melisma 是一个音节对应多个音符，不是“一音多词”。音乐生成还包括单声部或纯器乐，因此“音乐生成总是完整编曲”过于狭窄。

    2. 管线架构¶

    歌词 + 音符 + 速度 / 时序
    → 特定语言的发音与乐谱前端
    → 音符–音节–音素对齐及时长建模
    → 声学模型（频谱特征、F0、清浊音等控制）
    → 匹配的声码器 / 波形解码器
    → 歌声音频

    端到端模型可以联合训练其中多个阶段，但仍需处理时序建模和波形合成。

    2.1 前端与对齐¶

    • 按语言发音规则将歌词转为音素，明确处理声调、发音变体和跨语言音素。
    • 解析音高、起点、时长、休止、延音线、连音线、速度及已有歌词。
    • 普通 MusicXML/MIDI 通常不含音素-音频边界；边界需要标注、对齐、预测或通过专用格式提供。
    • 处理一个音节跨多个音符、一个音符内多个音素的情况。辅音可能在谱面元音起点前发出，因此平均分配音素时长通常不合适。
    • 在训练表示和系统支持的情况下，为换气和乐句边界分配时间。

    2.2 声学特征¶

    特征 含义 重要区别
    Mel 频谱图 / 频谱包络 时频能量或音色形状 所需表示取决于解码器
    F0 有声帧的基频 音符音高是目标，实际 F0 包含过渡和装饰
    清浊音标志 是否检测到或要求周期性发声 不等于静音或气息感
    非周期性、能量、气息控制 噪声、电平或表现性特征 因模型而异，不存在通用标准“s/δ”特征
    音素时长 发音与时间的对齐 属于时序变量，不是发声状态标志

    2.3 波形生成¶

    方法 架构 / 用途
    WORLD 使用 F0、频谱包络和非周期性的信号处理声码器
    HiFi-GAN / 神经源滤波变体 卷积对抗波形生成，部分变体显式使用 F0
    DiffWave 迭代扩散波形模型；速度和音质取决于 checkpoint 与采样
    Vocos 卷积骨干、傅里叶域输出及逆 STFT，并非默认的 Transformer 声码器
    SoundStream / EnCodec / DAC 解码器 从各自学习的编码表示重建音频，不能直接替换 mel 声码器

    Vocos 论文与实现 说明了其傅里叶合成方法。声码器需在目标歌声音域和采样率下验证；语音训练的 checkpoint 可能不能处理持续音或极高音。

    3. 代表模型¶

    3.1 早期方法与 XiaoiceSing¶

    单元拼接和统计参数合成早于现代神经 SVS。HMM/DNN 系统从语言和音乐输入建模声学特征与时序，其表现力和平滑问题取决于系统和数据。

    XiaoiceSing（Lu 等，INTERSPEECH 2020）采用 FastSpeech 式非自回归架构，通过歌声专用音高和时长约束预测频谱特征、F0 与时长；原系统使用 WORLD。不能将其描述为配备 HiFi-GAN 的自回归注意力解码器。

    3.2 DiffSinger¶

    DiffSinger: Singing Voice Synthesis via Shallow Diffusion Mechanism 作者为 Jinglin Liu、Chengxi Li、Yi Ren、Feiyang Chen、Zhou Zhao；2021 年预印，发表于 AAAI 2022。

    声学模型在乐谱条件下对 mel 频谱图去噪。浅扩散对简单解码器的预测施加中间噪声级别，利用学习/估计的边界缩短反向过程，再经声码器生成波形。这不意味着任意步数下都一定得到更好的质量。

    OpenVPI 的 DiffSinger 实现 扩展了原框架。多歌手/多语言、表现参数、加速采样和声码器支持取决于仓库版本及训练的声音库，不能将社区功能都归于原论文。

    3.3 VISinger 与 VISinger 2¶

    VISinger（Yongmao Zhang 等；2021 年预印，ICASSP 2022）将 VITS 适配到歌声，结合变分推断、归一化流、对抗波形解码、帧级先验、音高预测及音符感知时长模型。端到端训练仍包含显式时长建模。

    VISinger 2（Yongmao Zhang 等；2022 年预印，INTERSPEECH 2023）加入谐波/噪声 DSP 合成，引导波形解码并处理相位相关伪影，生成 44.1 kHz 歌声。

    3.4 DiTSinger 与商业工具¶

    DiTSinger（2025）研究扩散 Transformer、受字级时间范围约束的隐式音素对齐，以及合成数据构建流程。“隐式对齐”不代表完全没有音乐时序信息。

    ACE Studio 和 Synthesizer V 等商业乐谱/歌词编辑器是相关工程系统，但产品说明不是经过同行评议的架构描述。语言、声音库、插件和许可支持应按具体版本查询。

    3.5 相邻任务：SingSong 与全曲模型¶

    SingSong（Donahue 等，2023）从输入歌声生成器乐伴奏，适配 AudioLM，并使用源分离得到的人声/伴奏对训练。它不是扩散 SVS 模型，也不是歌声提取后再合成的方法。

    YuE、ACE-Step 等歌词到歌曲模型可生成带伴奏的人声，详见音乐生成。MusicGen 的 chroma 条件不保证歌词可懂、音符精确或音素时序正确。近似歌声的音频不等于经验证的 SVS 接口。

    4. 歌声表示与控制¶

    4.1 乐谱与音高¶

    表示 可提供的内容
    MusicXML 已编码的音符、时值、记谱、歌词与表情标记
    标准 MIDI 文件 音符事件和时序；可含歌词/文本元事件，但不要求音素对齐
    系统专用格式 系统支持的音素、音符归属、时长、F0 和表现参数曲线

    在 A4 = 440 Hz 的十二平均律下：

    \[ f(n)=440\,2^{(n-69)/12},\qquad c(f_1,f_2)=1200\log_2(f_1/f_2),\quad f_1,f_2>0. \]

    MIDI 音符号 \(n\) 指定半音网格。连续 F0 曲线表示音符间的颤音、滑音和音准偏移。音分表示相对指定参考的频率比，不是绝对频率单位；对以零表示的无声帧，该公式无定义。

    颤音速率和幅度随歌手、流派、声区及幅度定义（振幅或峰峰值）变化。不应把“5–7 Hz、20–50 音分”作为通用目标；直声也可能是有意选择。

    4.2 控制维度¶

    维度 可用条件 局限
    音高与时序 音符、F0、速度、音素时长 条件可能冲突或超出歌手训练音域
    歌手身份 歌手嵌入或参考录音 身份/风格泄漏和领域不匹配
    风格与情感 标签、参考音频、连续控制 标签不能保证感知因素独立
    气息与动态 模型特定的表现参数曲线 仅有清浊音开关不够
    技巧 假声、belting、怒音、vocal fry 标签或样例 需要相关数据和评测
    语言 发音前端和训练覆盖 共享音素符号不保证发音迁移

    5. 歌声转换（SVC）¶

    SVC 改变录制歌手的身份/音色，同时尽量保持歌词内容和时序。音高可以保持，也可以有意移调，须明确任务要求。它以源演唱为输入，与乐谱条件 SVS 不同。

    特征映射、内容/音高/歌手解耦、对抗解码与扩散都可作为组件。部分方法需要平行录音，许多方法使用非平行数据和自监督内容特征。扩散架构或目标歌手嵌入本身都不保证质量更高。

    So-VITS-SVC 是社区实现体系，须注明版本/分支。分别评价内容保持、音高、发音时序、伪影及目标歌手相似度。

    6. 公开歌声数据集¶

    以下数字对应所引版本，并区分歌曲、录音与歌手。

    数据集 语言 歌手数 内容
    Opencpop 普通话 1 100 首歌曲，3,756 条语句，约 5.2 小时；含音符/音素标注
    M4Singer 普通话 20 700 首歌曲，约 30 小时；乐谱标注与 SATB 声部
    NUS-48E 英语 12 20 首不同歌曲的 48 条歌唱录音；约 115 分钟歌声加 54 分钟歌词朗读
    JSUT-song 日语 1 27 首童谣，约 25 分钟，48 kHz
    Tohoku Kiritan 日语 1 50 首歌曲，约 57 分钟录音棚歌声

    VCTK 是语音数据，MUSAN 包含可供辅助用途的语音/音乐/噪声；二者都不是乐谱对齐的 SVS 语料。适合 SVC 的数据可能需要新增乐谱标注才能用于监督 SVS。分别查看每个版本的使用和再分发条件。

    按歌曲划分数据；测试未见歌手时还应按歌手划分。同一录音切片后分别放入训练集和测试集会造成泄漏。源分离人声可扩大覆盖，但仍含伴奏泄漏、伪影和不确定时序，不能等同于干净的录音棚分轨。

    7. 评测¶

    7.1 客观指标¶

    指标 须明确的设置
    F0 RMSE Hz 或对数频率/音分、对齐、音高提取器、有声帧掩码、八度错误处理
    F0 相关系数 共同有声帧；相关性不能检测恒定音高偏移，零方差时无定义
    清浊音错误 独立报告清浊音准确率/错误率，不能只在音高 RMSE 中忽略无声帧
    音符/音素时序 目标标注、起止容差、一字多音处理
    Mel / STFT 误差或 MCD 对齐参考、特征定义、归一化、系数选择及时间规整
    歌词错误 经验证的歌声转写、WER/CER 或音素错误，加人工可懂度
    歌手相似度 在歌声上验证过的嵌入模型，与参考歌手录音比较

    对共同有声且已对齐的帧集合 \(V\)，一种音分 RMSE 定义为：

    \[ \operatorname{RMSE}_{\mathrm{cent}}= \sqrt{\frac{1}{|V|}\sum_{t\in V} \left(1200\log_2\frac{\hat f_0(t)}{f_0(t)}\right)^2}. \]

    若 \(|V|=0\)，应报告无定义/缺失，不能记作完美的零误差。相对真实演唱的 F0 误差与相对理想音符的偏移不同：表现性颤音可能增加后者，却不意味着唱得差。

    7.2 听音测试¶

    按需要分别评价自然度、音质、发音、音乐时序、表现力和歌手相似度。MOS 与成对偏好是方法；PEMO-Q 是客观模型，不是主观听测协议。若结论涉及歌曲融合，应同时听独立人声和音乐上下文。

    明确听者人群、随机化、样本、置信区间及独立测试歌曲/歌手。客观频谱和音高误差衡量特定偏离，其与总体偏好的相关性应在具体环境验证。参见评测方法。

    8. 开放问题¶

    • 全曲中保持声音身份、歌词可懂度和富有表现力的分句。
    • 可控地学习发声技巧和情绪，同时避免意外改变歌手身份。
    • 从短参考泛化到未见歌手，并明确区分零样本推理与微调。
    • 跨语言、长元音和一字多音的稳健音素/音符对齐。
    • 低延迟交互：除总体实时倍率及硬件，还应报告首段音频延迟。
    • 跨风格和文化评测；Opencpop 等常用数据集并不构成所有 SVS 任务的通用协议。
    • 集成主唱、和声与伴奏，并能控制各声部。
